# Source Lists in Godot's CMake Build System

## Overview

The Godot CMake build system uses separate source list files to manage the thousands of source files across the codebase. This approach has several advantages:

1. **Maintainability**: Source lists are automatically generated, so you don't need to manually update them when files are added or removed.
2. **Modularity**: Each component has its own source list file, making it easier to understand the codebase structure.
3. **Flexibility**: You can include specific source list files as needed, or include all of them at once.

## Source List Files

Source lists are stored in the `cmake/source_lists/` directory with the following naming convention:

- `GODOT_CORE_sourcelist.cmake` - Core functionality
- `GODOT_DRIVERS_sourcelist.cmake` - Platform-specific and hardware drivers
- `GODOT_PLATFORM_sourcelist.cmake` - Platform abstraction
- `GODOT_SCENE_sourcelist.cmake` - Scene system
- `GODOT_SERVERS_sourcelist.cmake` - Server abstractions
- `GODOT_EDITOR_sourcelist.cmake` - Editor functionality
- `GODOT_MAIN_sourcelist.cmake` - Main executable functionality
- `GODOT_THIRDPARTY_*_sourcelist.cmake` - Third-party libraries

Each file defines three variables:
- `GODOT_*_SOURCES` - Contains source files (.cpp, .c, .mm, .m)
- `GODOT_*_HEADERS` - Contains header files (.h, .hpp)
- `GODOT_*_FILES` - Contains both source and header files

For example, `GODOT_CORE_sourcelist.cmake` defines:
- `GODOT_CORE_SOURCES`
- `GODOT_CORE_HEADERS`
- `GODOT_CORE_FILES`

## Platform-Specific Driver Sources

The drivers component is special because it contains platform-specific code that should only be compiled for the target platform. To handle this, we use a separate approach:

1. `GODOT_DRIVERS_sourcelist.cmake` - Contains all driver source files (used for reference and headers)
2. `GODOT_DRIVERS_PLATFORM_sourcelist.cmake` - Contains platform-specific source files organized by platform

### Path Handling for Drivers

The platform-specific driver source files are stored with paths relative to the drivers directory. For example:

```cmake
# Windows drivers
set(GODOT_DRIVERS_WINDOWS_SOURCES
  d3d12/d3d12_hooks.cpp
  wasapi/audio_driver_wasapi.cpp
  ...
)
```

In the drivers/CMakeLists.txt file, these paths are converted to full paths relative to the source directory:

```cmake
# Convert platform-specific paths to full paths
set(GODOT_DRIVERS_FULL_PATHS)
foreach(SOURCE_FILE ${GODOT_DRIVERS_ACTIVE_SOURCES})
  # Check if the path already starts with "drivers/"
  if(SOURCE_FILE MATCHES "^drivers/")
    list(APPEND GODOT_DRIVERS_FULL_PATHS "${SOURCE_FILE}")
  else()
    list(APPEND GODOT_DRIVERS_FULL_PATHS "${CMAKE_CURRENT_SOURCE_DIR}/${SOURCE_FILE}")
  endif()
endforeach()

# Create the library with correct paths
add_library(godot_drivers STATIC ${GODOT_DRIVERS_FULL_PATHS})
```

This approach ensures that the source files are correctly located regardless of the current working directory or the location of the CMakeLists.txt file.

### Platform-Specific Variables

The platform-specific file defines the following variables:
- `GODOT_DRIVERS_WINDOWS_SOURCES` - Windows-specific driver sources
- `GODOT_DRIVERS_MACOS_SOURCES` - macOS-specific driver sources
- `GODOT_DRIVERS_IOS_SOURCES` - iOS-specific driver sources
- `GODOT_DRIVERS_UNIX_SOURCES` - Linux/Unix-specific driver sources
- `GODOT_DRIVERS_COMMON_SOURCES` - Common driver sources for all platforms
- `GODOT_DRIVERS_VULKAN_SOURCES` - Vulkan-specific driver sources
- `GODOT_DRIVERS_ACTIVE_SOURCES` - The final list of driver sources for the current platform

When you build Godot, CMake automatically selects the appropriate drivers based on the target platform. This ensures that only the necessary code is compiled.

## Generating Source Lists

Source lists are generated by the `cmake/GenerateSourceLists.ps1` script, which scans the repository and creates source list files for each component.

```bash
# Navigate to the root of the Godot repository
cd /path/to/godot

# Run the script
pwsh cmake/GenerateSourceLists.ps1
```

The script does the following:
1. Scans each component directory for source files
2. Creates a separate source list file for each component
3. For drivers, creates both a complete source list and a platform-specific source list with paths relative to the drivers directory

## Using Source Lists in CMakeLists.txt

You can include a specific source list:

```cmake
include(${CMAKE_SOURCE_DIR}/cmake/source_lists/GODOT_CORE_sourcelist.cmake)

add_library(godot_core STATIC ${GODOT_CORE_SOURCES})
```

Or include all source lists at once:

```cmake
include(${CMAKE_SOURCE_DIR}/cmake/source_lists/all_sourcelists.cmake)
```

For drivers, use the platform-specific approach:

```cmake
# Include both source lists
include(${CMAKE_SOURCE_DIR}/cmake/source_lists/GODOT_DRIVERS_sourcelist.cmake)
include(${CMAKE_SOURCE_DIR}/cmake/source_lists/GODOT_DRIVERS_PLATFORM_sourcelist.cmake)

# Convert paths to full paths
set(GODOT_DRIVERS_FULL_PATHS)
foreach(SOURCE_FILE ${GODOT_DRIVERS_ACTIVE_SOURCES})
  list(APPEND GODOT_DRIVERS_FULL_PATHS "${CMAKE_CURRENT_SOURCE_DIR}/${SOURCE_FILE}")
endforeach()

# Create the library using the platform-specific sources with correct paths
add_library(godot_drivers STATIC ${GODOT_DRIVERS_FULL_PATHS})
```

## Modifying the Source List Generator

If you need to modify how source lists are generated:

1. Edit `cmake/GenerateSourceLists.ps1`
2. Run the script to regenerate the source lists
3. Commit both the script changes and the generated files

For platform-specific drivers:
1. Edit the `Generate-DriversSourceList` function in the script
2. If you add a new driver subdirectory, add it to the appropriate platform folder list

## Best Practices

- Always regenerate source lists after adding or removing files to keep them in sync
- Include source lists at the beginning of your CMakeLists.txt files
- Use the appropriate variable (SOURCES, HEADERS, or FILES) depending on your needs
- For drivers, use the platform-specific source list to avoid compiling unnecessary code

## Troubleshooting

If you encounter issues with the source lists:

1. Make sure the `cmake/source_lists/` directory exists
2. Verify that PowerShell Core (pwsh) is installed
3. Run the generator script again to update the lists
4. Check that the CMakeLists.txt files are including the correct source list files
